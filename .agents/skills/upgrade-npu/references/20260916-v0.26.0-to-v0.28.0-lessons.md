## Upstream changes that mattered

| Contract | Classification | Preserved invariant / adaptation |
| --- | --- | --- |
| Modular MoE factory and internal router | Behavioral | Refresh native model factory binding before FFN construction; test the actual constructed owner and native forward. |
| W8A8 quant-method apply consumes selected IDs/weights | Behavioral | Rebase on target `quantization/methods/w8a8/w8a8_dynamic.py`; change only IDs for opt-in balancing, preserve weights. |
| Runner metadata/dummy lifecycle adds DCP/GDN/KVPP state | Behavioral | Copy target skeletons and replay AFD stage ownership; retain exact signatures and native lifecycle. |
| Native model owns final SP gather | Behavioral | Remove duplicate runner-level gather rather than preserving obsolete code. |
| Strict Ascend config factory | Behavioral | Filter AFD-owned keys at `init_ascend_config`; preserve caller mapping and native cache/singleton. |
| Config construction precedes worker setup | Behavioral | Install namespace adapter at NPU plugin registration and config patches before both parent/child validation. |
| Backend normalization mutates config hashed across processes | Behavioral | Finalize backend before serialization using raw upstream selectors; retain hash checks. |

Architecture decision: these synchronous contracts map to narrow local seams;
no execution-engine redesign or feature removal was needed. This decision does
not qualify the excluded asynchronous path.

The namespace adapter rebinds a fixed list of already-loaded aliases without
forcing optional imports, scanning modules or modifying function code objects.
Remove it when upstream accepts plugin namespaces. Remove DBO platform/config
wrappers when upstream supports plugin-owned ubatching. Retain the scoped MLA
graph resolver until upstream accepts per-forward-context graph registries.
Retire W8A8 copied methods when upstream exposes an expert-ID profiling hook.

## Failures and root causes

1. Missing `tenacity` prevented evaluation before requests: environment-only
   installation, no runtime compatibility patch.
2. Strict config rejected `afd`. Worker-time patch installation was too late:
   both spawned-child revalidation and scheduler direct calls precede workers.
   Fresh-process config and scheduler probes exposed these separate paths.
3. DBO captured successfully but failed READY config hashes. Parent retained
   `allgather_reducescatter`; fresh child normalized to `flashinfer_all2allv`.
   Comparing complete config fields isolated the backend. Ascend clears the
   final DSA-CP flag after selecting the backend, so read raw additional-config
   selectors to reproduce its order. Hash equality was restored without
   disabling validation.
4. 2A1F eager completed requests but generated unrelated repeated text (0/7).
   CAMP2P kernels divide FFN buffers into equal per-Attention chunks, whereas
   eager DP permits unequal lengths. Real 3-rank equal 1/4/128-token roundtrips
   passed; unequal 4/2 failed A2E and E2A. Enabling existing DP padding for
   CAMP2P fan-in restored 2/7. The omission also existed in the AFD base;
   this was discovered during qualification, not proven introduced upstream.
5. Selecting the entire model test module included six GPU-only V2 cases.
   `validate_topology` rejected the first before startup. Existing
   `tests/e2e/README.md` and base code already document this boundary. Select
   seven explicit NPU node IDs; do not expand support or manufacture skips.

## Validation and environment lessons

See the [version-scoped recipe](../../../../recipe/npu/CAMP2pAFDConnector/deepseek_v2_lite/README.md)
for commands, metrics and software stack. Native TP1 eager returned `Paris`.
Seven NPU basic cells passed, each strict/flexible GSM8K-7 score 2/7.
Scoped units: 970 passed, 3 skipped, 1 deselected, with three DSV4 async test
files excluded. The skipped cases are one opt-in two-rank kernel test and two
missing-extension tests when the extension is installed. Ruff/format/compile,
exact active signatures and diff checks passed. Source-comment-only follow-up
was checked with AST comparison.

Full GSM8K started, then was cancelled by requester instruction with SIGTERM.
No full-dataset score exists. Serving processes, ports and NPU processes were
confirmed clear; the exit status from cancellation is not an accuracy failure.
FastAPI conflict was explicitly accepted; other inherited optional-tool
conflicts remain. A passing runtime test does not certify `pip check` cleanliness.

The validation container was recreated once, losing `/tmp` artifacts. Rebuild
from frozen source into persistent storage and verify identity again. A venv
with system-site-packages inherits distributions but may lack `venv/bin/vllm`;
check the executable before starting a suite. For offline GSM8K, verify the
actual `openai/gsm8k` repo-ID cache load, not only direct local parquet loading.
The runner uses `AFD_GSM8K_LIMIT=all` for 1319 samples; **unset means seven**.
Do not rely on an outdated skill sentence claiming unset runs the full dataset.

## Documentation and process lessons

Replace stale “NPU upgrade pending” claims only for validated synchronous cells.
Retain v0.19/v0.26 V3.2 recipes and asynchronous accuracy as historical evidence.
Document native final-gather ownership consistently with the new runner.
A backend-neutral test module can contain backend-specific cases; inventory
its selection guards before computing the gate size.

Earlier changes had independent agent reviews. After the requester switched
model-speed requirements to Standard, agents remained paused because their
live tier could not be verified by available tools; final padding and document
changes received separate frozen-diff primary review. Do not claim an
independent review that did not occur. Keep root causes in signed-off commits.

## Reusable principles

- Validate all config consumers: registration, parent construction, spawned
  revalidation, scheduler initialization and worker setup are separate paths.
- Compare normalized state before changing checks; never bypass hash validation
  to conceal ownership or ordering errors.
- Test transport independently with unequal rank workloads. Equal-size tests
  cannot prove fan-in correctness.
- Preserve native numerical ownership; changing IDs for profiling must not
  accidentally replace routing weights.
- Small-sample functional success and full accuracy are distinct evidence.

## Version-specific facts and next-upgrade checklist

Re-derive the strict factory's keys, fixed alias list and raw FlashComm/DSA-CP
selector order at the next pinned commit. Recheck exact metadata/dummy and
warmup signatures, final gather ownership, MoE factory binding and W8A8 apply.
Repeat unequal-token CAMP2P probes before changing padding or transport code.
Padding costs extra eager work on underloaded ranks; removing it requires a
variable-length kernel protocol, not merely native MoE support.

Still unqualified here: NPU V2, async CAM/DSV4, W8A8 hardware, Attention-side
gating, additional TP/EP/PCP/speculative/multi-node combinations and full GSM8K.
No performance claim or canonical release-image qualification is implied.
