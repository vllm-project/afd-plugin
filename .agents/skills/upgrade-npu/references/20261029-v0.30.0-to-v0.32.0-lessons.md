# Lessons from the vLLM 0.30.0 to 0.32.0 NPU upgrade

## Runtime identity and scope

- Original AFD baseline: `7452d52748fec2a858b63e4cb22941dadd7a3ee3`; tested production tree: `84c2ebaac3890d993deaa1876af7457c2aa2ea8d`.
- Previous vLLM `ced6857afa0ea7b2e3f0846a62e1394e90f15607` and vLLM-Ascend `8d4409d6256d8a6729140ddcc0d1889e3f96cdd6`; target vLLM v0.32.0 `5df63a7203cdb9328d824a27b682e77c7b9928be` and vLLM-Ascend `bd42eea01d8312c4df469fabaed45f77a12df4d3`.
- Tested A3/910C stack: Python 3.12.13, PyTorch 2.10.0+cpu, torch_npu 2.10.0.post7, CANN 9.2, Triton Ascend 3.6, memfabric-hybrid and memcache-hybrid 1.3. Six specified dependency conflicts were explicitly accepted; `pip check` remained a failure.
- Scope: single-Pod V2-Lite CAMP2P eager, graph, graph+DBO, and Async CAM uBatch; DSV4 W4A8 native/async first100, including real request-window Attention DBO, and W8A8 smoke/checkpoint-specific checks. See [validation](https://github.com/vllm-project/afd-plugin/pull/507) for exact cells, evidence grades and retained exit failures. Multi-Pod, V4 synchronous end-to-end Graph/DBO, separate V4 DBO boundary/freshness checks and broader long-prefill qualification were outside this acceptance; no performance qualification is claimed.

## Upstream changes that mattered

The architecture gate classified the release changes as local API/lifecycle adaptations rather than an authorized redesign. The shared engine startup/coordinator contract changed; native MRV2 execution, DP dispatch, Ascend configuration, graph metadata, SP ownership and model construction changed at their respective seams. AFD must preserve Attention request/KV ownership, connector-driven FFN lifecycle, control/transport ordering and platform separation. See [compatibility and patches](../../../../docs/design/module/compatibility_and_patches.md), [runtime matrix](../../../../docs/design/module/execution_platforms.md), and commits `d29db75`, `2e30083`, `49dc295`, `3eec8b4`, `d85159b` and `e6ced6c`.

## Adaptations and patch lifecycle

Rebase necessary patches onto the pinned upstream bodies and signatures, keep AFD changes narrow, and retain AFD/non-AFD tests and removal triggers. Both devices now share the vLLM 0.32 version policy while preserving backend-specific execution. EngineCore, async-DP, platform normalization and MRV2 ubatch adapters remain in the compatibility inventory. W8A8 Attention gating must retain its scales after native quantization finalization.

Check GPU fixes per backend before reusing them. NPU shares control-plane close/codec groundwork but does not implement the complete GPU receive-cancellation and join-before-destruction guarantee. The four CUDA V4 fixes for positions/KV alignment, padding-only Attention, indexer SM budgets and per-owner FlashMLA workspace do not qualify Ascend's separate DSA/CANN boundaries.

## Failures and root causes

- Custom op-api dependency leakage affected the built-in routing reference; `5faf111` isolates the dependency and `ef1a1a6`/`532bbda` isolate the reference process. Confirm loaded native libraries, not just the package version.
- Sparse CAM test input exceeded the configured receive capacity; `bbe9aaf` fixes the test fixture without increasing the runtime tolerance.
- A later controller replaced CANN's `PYTHONPATH`, so startup could not import `acl`. Preserve the original environment; retain the startup failure and rerun only affected entries.
- The initial sample-hash checker used a different JSON serialization from lm-eval. Two already completed Graph entries were rechecked offline using the evaluator's serialization and original artifacts; their original controller failures remain recorded. Confirm samples and prompts independently of score and do not silently rewrite failures.
- The earlier AFD long-prefill answer failures were followed by a same-input 1501-token native control that also failed, with 8/10 correct. Retain both results and distinguish the native answer issue from AFD parity; neither the later GSM8K pass nor the CUDA workaround identifies or fixes that root cause.
- Physical device allocations can be noncontiguous; verify mapping before launching a topology with contiguous-device assumptions. A transient empty iTask status response is not proof that a job ended: inspect state before starting or stopping anything.

## Validation and environment lessons

The target `tests/unit` run recorded 1843 passed, six skipped, 180 subtests passed. Four device invocations had separate hardware coverage; two mutually exclusive absence cases skipped because the extension was present. The hardware and functional gates precede accuracy. The eight agreed Lite cases used identical first 100 GSM8K documents and prompts, eight-shot, max generation 512, strict match >= 0.27; all passed their request/path and accuracy gates. Seven AFD graceful exits failed, while native control's strict exit passed; physical cleanup and scheduler release were independently verified. See the [validation record](https://github.com/vllm-project/afd-plugin/pull/507) and [NPU tests](../../../../docs/npu/TESTING.md).

The V4 W4A8 native/layered-off/layered-on/DBO first100 entries scored 96/95/94/95 for both strict and flexible filters, using the same documents, rendered prompts and targets, eight-shot, max generation 512 and concurrency 12. The eager Attention DBO entry used DP2/TP4 with FFN DP8/TP1 ordinary GMM; each DP0 Attention TP rank recorded 42 completed two-nonempty-microbatch steps and each DP1 TP rank recorded 44 during evaluation. This qualifies the agreed request-window cell, not per-question stage splitting, A/F transaction freshness, padding-only or other V4 boundary tests. V4 native DBO was outside the pinned Ascend runtime's support. These are the explicitly agreed 100-sample results, not 1,319-question qualification.

The clean test overlay matched the committed runner/helpers while production and target native identity were verified separately. All 16 V4 DBO A/F workers mapped the frozen AFD native artifact; the audit did not cover every system-library mapping or complete weight contents. Native V4 exited gracefully; the AFD exit failures remain disclosed even though device processes, ports and the dedicated allocation were released.

Preserve original logs, archive/hash evidence before releasing a task, and distinguish request completion, output correctness, actual path execution, graceful exit, physical cleanup and scheduler release. A post-request exit exception is not an exception for startup, accuracy, identity or cleanup. Correct simple recoverable mistakes within the running task when safe rather than restarting merely because a command failed.

## Documentation and process lessons

The prior docs mixed an NPU 0.30 pin with the shared GPU 0.32 pin and contradicted themselves about synchronous graph+DBO. Update active targets and support statements from the measured cells; keep old recipe commands and 300-question results historical. Review both raw artifacts and synthesized receipts independently, and freeze the source identity when interpreting results.

## Reusable principles

Compare both upstream revisions before implementation; validate a native control before relying on plugin behavior. Separate exact source, native library, image and data identity. Use the first informative failure, avoid widening test scope or modifying tolerances, and rerun only the evidence invalidated by a change.

## Version-specific facts

The named runtime revisions, package stack, six accepted conflicts, exit failures, scoring outcomes and deferred scenarios belong only to this upgrade and environment; none establishes behavior on other versions or hardware.

## Remaining debt and next-upgrade checklist

- Graceful AFD exit remains unresolved; the complete GPU receive-cancellation fix is not implemented on NPU. V4 request-window DBO passed, while separate position/KV, padding-only, indexer, workspace and A/F freshness boundaries remain unqualified. Native and AFD long-prefill answer failures and Ascend multi-Pod 507034 remain recorded with causes not established.
- Check the compatibility inventory's target symbols and upstream removal triggers, exact MRV2 graph/ubatch/DP paths, model/gate weight and operator references, generated metadata, and target-native imports before the next migration.
- Freeze device layout, checkpoint/quantization, data/prompt identities, score oracle, exit policy and cleanup evidence before running hardware gates. Keep old results attached to their original revisions.
