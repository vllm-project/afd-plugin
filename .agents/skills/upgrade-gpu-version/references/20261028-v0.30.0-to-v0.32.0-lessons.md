# Lessons from the v0.30.0 to v0.32.0 GPU upgrade

This is historical evidence for the stated revisions and tested configurations,
not a substitute for checking the next upstream version.

## Runtime and scope

- AFD base `f5ef631873aa242acd0f1984602cf2c437b7a3d0`; GPU-tested code
  `972d8842a29e74e36cf5b1abc42bcfbc0539e40f`; full CPU tests used the
  test-only follow-up `74d2229b2268ce03d3c2afe75a5d37ca9050062b`.
- vLLM GPU moved from `0.30.0` (`ced6857afa0ea7b2e3f0846a62e1394e90f15607`)
  to `0.32.0` (`5df63a7203cdb9328d824a27b682e77c7b9928be`); Ascend remains
  on its prior 0.30 source pair and was not tested on NPU hardware here.
- H20-3e, up to four GPUs: Python 3.12.13, PyTorch `2.13.0+cu130`, CUDA
  toolkit 13.0.48, driver 580.105.08, GCC 10.2.1 and NCCL 2.29.7. The
  tested connector was `P2pNcclAFDConnector`; V2-Lite, V4 Flash, Qwen3 MoE
  and Qwen3.6 MoE had selected native and AFD cases.
- Accuracy comparisons were limited to selected first-300 GSM8K cases. Native V4
  DBO was excluded by the user; ordinary native Graph was the reference. The
  separate V2 graceful-shutdown defect was also excluded from blocking this
  upgrade, while its actual failed shutdown results were retained.

## Upstream changes and adaptations

- CUDA workers use the upstream `_make_model_runner` factory rather than the
  former startup-time runner substitution. Preserve native worker lifecycle,
  use role-specific runners, and recheck signatures on the pinned upstream.
- EngineCore lifecycle and MRV2 graph/ubatch interfaces changed. GPU patches
  were replayed against 0.32, while shared code retained the NPU 0.30 branch.
  `808a432` corrected a version guard that otherwise skipped that NPU path;
  CPU contract tests do not replace NPU hardware validation.
- DeepSeek V4 exposed stage input alignment, padding-only ubatches, indexer SM
  scheduling and workspace-reservation seams. Commits `4834e1d`, `03f96f6`,
  `2867154` and `972d884` address these separately. The workspace fix reserves
  each actual V4 ubatch/lane before native profiling and retains upstream
  workspace locking and memory accounting. Source capacity analysis shows
  its reservation covers indexer scratch for the recorded
  L4096/T1024/default-factor-5/FP8/non-CP case; broader coverage is unproven.

## Failures and useful evidence

- V4 workspace could grow after Graph capture had locked a smaller buffer.
  Reserve each lane's actual workspace before profiling; do not infer the
  root cause of an earlier hang merely from a later diagnostic failure.
- V4 limited-sample Graph DBO and native Graph comparisons passed their
  recorded criteria. Source-specific results and cleanup caveats belong to
  the linked validation matrix; they do not establish output equivalence or
  full-dataset accuracy.
- V2 TP2 Graph DBO and DP2 eager DBO passed inference/oracles but needed
  force killing during shutdown. A similar symptom appeared on 0.30;
  do not relabel these runs graceful passes or infer a shared root cause.
- Full-suite CPU validation exposed fake EngineCore decorator leakage and an
  obsolete method-identity assertion. Isolate fixtures without weakening the
  real signature contract; individually passing tests can contaminate others.
- Comprehensive review found that the CUDA V4 stage-input adapter was also
  reachable by NPU V4 Async CAM DBO. Its CUDA-only state and 0.32 attention
  signature do not apply to Ascend 0.30. Gate it by the actual device and
  cover both Async and control-plane stage preparation on CPU; this does
  not constitute NPU hardware validation.
- On this environment, PyArrow's allocator background thread caused a native
  import crash before AFD execution; `JE_ARROW_MALLOC_CONF=background_thread:false`
  made the native import and tests work. Treat this as environment-specific.

## Documentation and process lessons

- Keep hardware, CPU-only, historical and excluded claims distinct. The
  [runtime matrix](../../../../docs/design/module/execution_platforms.md#tested-runtime-matrix)
  records the measured cells, score limits and shutdown caveats. Checked-in
  recipes were inspected but not all were executed as recipes.
- Freeze source and runtime identity per test, preserve raw failed results,
  and verify owned process/IPC/port cleanup and scheduler release. Tests that
  pass individually can still contaminate a complete suite through module
  reloads; exercise the full suite after fixture changes.
- Later V4-specific changes were not a retest of other models on the final GPU
  code. Some non-V4 first-300 runs used a private 12-concurrent-request test
  runner overlay; do not infer performance or serial equivalence.

## Next-upgrade checks and remaining debt

- Recheck exact native signatures, decorators, graph replay, ubatch input
  ownership, FlashMLA workspace lifecycle and model-specific SM budgets.
- Revisit V2 shutdown independently; retain the forcekill result until a clean
  run proves a fix. Review exact recipes, cross-node transports, NPU hardware,
  native V4 DBO, full-dataset accuracy and other untested topologies separately.
- Assess whether upstream exposes stable hooks that can remove the remaining
  scoped graph, profile and EngineCore adaptations.
