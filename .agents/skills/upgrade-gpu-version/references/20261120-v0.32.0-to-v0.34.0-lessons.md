# Lessons from the v0.32.0 to v0.34.0 GPU upgrade

Use these results for the stated revisions and configurations. Check the
exact upstream source again on the next upgrade.

## Runtime identity and scope

- AFD base `40b4a49cf153a8c8a0247fe96662378b743330af`. Adaptation commit
  `65d863386292b5af33d1656d7c54670206c4b566`. The new V4 AFD DBO and
  DeepEP M2N runs used source tree
  `b83e54d38087308c0c2ff31c3b8a470acf81fe73`. The later shared capture
  fix retained the CUDA arguments and capture metadata flow.
- GPU vLLM moved from `0.32.0` (`5df63a7203cdb9328d824a27b682e77c7b9928be`)
  to `0.34.0` (`62d4bc3c7e33b1b6c906e233e6af2d3506c482ca`). The Ascend
  source pair kept vLLM 0.32.0 and vLLM-Ascend `bd42eea0`.
- Single-node H20-3e, up to four GPUs per case. Python 3.12.13, PyTorch
  2.14.0+cu130 with C++11 ABI, CUDA 13.0 and NCCL 2.30.7. The qualification
  used the first 300 GSM8K examples per selected case and carried forward
  the earlier passing runs.

## Upstream contracts

- vLLM 0.34 removes Model Runner V1. Keep native V2 worker startup and audit
  the Attention and FFN entry points before removing old runner checks.
- Extensible KV cache settles its capacity after warmup. Preserve the
  worker capability decision, measured capacity, second context-length
  sync and cache extension when porting EngineCore. The AFD FFN bypass
  stays ahead of the Attention KV lifecycle.
- CUDA `UBatchRunner.prepare` takes a batch descriptor and DP sync state.
  The graph-preparation helper also adds `slot_mappings_buffer`. The shared
  Ascend wrapper must call the 0.32 signature without that keyword. Use
  a strict test double or the pinned runtime to expose argument drift.
- V4 hash-MoE layers come from `mlp_layer_types`. Check execution probes
  that consume model configuration at the same time as the adapters.

## Failures and validation

- Native V4 Flash DBO eager and graph failed in vLLM 0.34 warmup on H20
  with AFD disabled. The second microbatch can present an unaligned
  positions view to the CuTeDSL compressor. The native eager and Graph
  controls without DBO passed. The AFD stage-alignment adapter supported
  both AFD DBO variants, with two-stage execution and actual Graph replay.
- For afdEP-comm 1.1.0 and PyTorch 2.14, use a C++20 host build and matching
  NCCL headers and runtime. The H20 driver exposed `libcuda.so.1` but the
  linker also needed `-lcuda`. Supplying the toolkit stub through the
  link-time search path preserved loading of the real driver.
- Qwen3 M2N cold Attention warmup exceeded the default 120-second AFD
  process-group timeout. `afd_process_group_timeout_s=600` let the H20
  cases use the original validation checks. The ten M2N cases passed,
  including all-rank Graph replay and two-stage DBO where required.
- Keep shutdown diagnostics and resource release evidence together.
  V4 AFD evaluation and cleanup passed, with errors logged during
  teardown. A separate vLLM 0.32 API check passed eight signatures, then
  needed a follow-up to verify transient compiler helpers had exited.

## Remaining validation

The [0.34 upgrade record](https://github.com/vllm-project/afd-plugin/pull/617)
describes the tested single-node configurations. Cross-node, profiling,
full-dataset accuracy, and Ascend hardware coverage require their own evidence.
